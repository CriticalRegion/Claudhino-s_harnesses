Known so far: $ARGUMENTS
This is the per-hackathon setup interview: the human answers, you apply; never skip a question by assuming the answer. Keep each message short. Never turn on autonomous or solo mode here.
0. State: run `hk status` and `hk migrate-v3`. Not a git repo with at least one commit: stop and say so. v3 files found: show the list and, with the human's OK, run `hk migrate-v3 --apply`; if CLAUDE.md still has v3's "# Hackathon mode" section, show it and, with their OK, delete only that section (the plugin injects the rules now).
1. Project pieces (first run, or after a plugin update): `hk install-project` (defaults: `--model sonnet --mcp github,vercel --ponytail on`; step 5 may change them).
2. You: if `hk status` says "not set up in this clone", ask the human's team handle (short, lowercase) and run `hk init <handle>`. It creates or joins the team board (a separate `hackathon-state` branch on the remote); it never pushes code.
3. Joining a configured team? If `hk config show` shows `(team)` values, the event is already set up: do only step 6 (their personal model), step 7 (Discord) and step 8. Otherwise continue.
4. Event, in one plain-text message the human can partly skip: event name and URL; deadline (local time); brief/theme; sponsor or required tech; judging criteria and weights; submission requirements (video length, public repo, live URL, pitch length); team members with skills and when each person's 5-hour usage window starts; links (Devpost, Discord, docs). Fill the "## Event" section of `.hackathon/PLAN.md` ("unknown" for skipped lines) and write the deadline to `.hackathon/deadline` as `YYYY-MM-DDTHH:MM`, nothing else. Event URL given and no `.hackathon/RESEARCH.md`: offer `/hackathon:research`. Also ask: "Do you already have an idea, or should kickoff generate and score ideas?" If they have one, put it in PLAN.md's one-line pitch and include `ideation=off` in step 5c.
5. Profile and toggles. ALWAYS ask this with AskUserQuestion, even when the human gave lots of detail; never choose the profile for them:
   a. Profile: **sprint** (Recommended: lean and fast; guard and stop check off), **crunch** (autonomous-ready: auto-approve, 6h autonomous budget, collisions warn instead of refuse, pre-push checks off), **careful** (build it properly: demo-first off, reviewer, guard and stop check on).
   b. One multi-select, "Change anything from that profile?": Rules and modes / Notifications / Tools / Timing. For each group picked, ask its toggles with the profile's value as the default (`hk config show` lists them):
      - Rules and modes: ideation (kickoff generates ideas / you bring your own), demo_first, auto_budget, collision (refuse/warn/off), loop_guard, reviewer, guard, stop_check, config_protect
      - Notifications: midtask, wake and wake_cap, contract_alerts, notify (desktop), and Discord (step 7)
      - Tools: ponytail, GitHub and Vercel MCP (or the gh / vercel CLIs), default model, prepush, autoapprove (approve prompts even outside autonomous mode)
      - Timing: polish_at (minutes before the deadline, 240), freeze_at (60), stale_min (45), budget_usd (0 = none)
   c. Apply in ONE command so the human approves once: `hk config profile <p>` plus, if they changed toggles, `&& hk config set k=v k=v ...`. If Tools changed ponytail, MCP or the model, re-run `hk install-project --model <m> --mcp <github,vercel|none> --ponytail <on|off>`.
6. Models, in one line: kickoff, judge and deep run on Opus; building runs on Sonnet. Anyone who wants Opus as their own main model: `/model opus` (or `"model": "opus"` in their `.claude/settings.local.json`).
7. Discord (personal): `hk discord status`. Not set: ask for a Forum channel's webhook URL, or skip. Set it with `hk discord <url> --global` and, with their OK, `hk discord test` (it posts to the channel). Never write the URL into a file in the repo or a message.
8. Finish: commit what exists of `.hackathon/PLAN.md .hackathon/deadline .hackathon/IDEAS.md .hackathon/bin .githooks .gitignore .gitattributes .claude/settings.json .mcp.json` (ask before pushing), run `hk status`, and say in at most 5 lines what's set and what the human must do: `/reload-plugins` (or a new session) if settings changed, `/mcp` to sign in to github and vercel, teammates install the plugin and run `/hackathon:setup`. Offer `/hackathon:kickoff`.
