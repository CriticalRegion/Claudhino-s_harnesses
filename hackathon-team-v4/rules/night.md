Night shift (a line says NIGHT SHIFT or NIGHT ON; humans are away). The goal and its "Done when" list are in `.hackathon/state/NIGHT.md`: they define done, not your taste. The autonomous rules apply, plus:
- Your loop: claim a task (`hk claim <id>`) -> `git switch -c night/<id> origin/main` -> build it -> `/hackathon:verify` -> `git push -u origin night/<id>` -> `hk submit <id>` -> take other work while it's reviewed. The Stop hook names your next step; when it says nothing, stop: a REVIEW or VERDICT for you, or new work, wakes you.
- `REVIEW @you: <id>` comes first: run `/hackathon:review <id>` before your own building. Be a strict, useful critic: real problems only, numbered, MUST / SHOULD / NIT with path:line and a concrete fix. A MUST is something that breaks a Done-when item, the demo, a teammate's contract, or security. Approve when there are no MUSTs.
- `VERDICT @you: <id> CHANGES`: fix every MUST (SHOULD if cheap) on the same branch, push, then `hk submit <id> --note "fixed 1,3; 2 disputed: <why>"`. Dispute a finding at most once, with a reason; the reviewer decides. Rounds are capped: at the limit the work is accepted and the rest becomes a follow-up task.
- `APPROVED` / `ACCEPTED`: `git fetch && git rebase origin/main` on the branch, run the checks, then `git switch main && git pull --rebase --autostash && git merge --no-ff night/<id> && git push` (the pre-push check must pass; never bypass it), then `hk done <id> <path:line>`. Never merge anything that wasn't approved; `hk done` refuses.
- Stay inside the goal. An idea outside "Done when" goes to `hk log "IDEA <one line>"` for the humans, not into code.
- When the board empties, hk adds `goal-N`: whoever claims it runs `/hackathon:goal-check`. New gap tasks follow; the shift ends on GOAL MET, the time limit, the budget, or the goal-check limit, and writes the morning report itself.
- Talk only through hk (submit, verdict, log, decide). Never message another agent in chat or loop on a disagreement: one dispute, then the reviewer's verdict stands.
